# VIT Chennai Campus — AI Digital Twin & Wayfinder Navigation System

A high-performance, AWS-ready 3D AI Digital Twin of the **Vellore Institute of Technology (VIT) Chennai campus**, built using Three.js, real extracted Wayfinder topological navigation data, dynamic occupancy telemetry simulation for the Mahatma Gandhi Auditorium (Building024), and Dijkstra shortest-path emergency evacuation routing.

---

## 📐 Coordinate System Diagnosis & Verification

A critical constraint of Phase 2 is verifying the alignment between the Wayfinder dataset and the GLB coordinate system. Rather than guessing transforms or manually offsetting positions, coordinate alignment was systematically diagnosed by comparing the glTF node translations against the Wayfinder entrance coordinates.

### Diagnostic Proof

| Campus Location | glTF Node | glTF Center (X, Z) | Entrance Waypoint | Waypoint (X, Z) | Euclidean Delta | Coordinate Match |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Mahatma Gandhi Auditorium** | `Building.024` | `(90.5, 325.5)` | **WP 199** | `(70.3, 328.5)` | 20.5 m (at doorway) | **1:1 Native Match** |
| **Main Gate** | `Main_Gate` | `(-120.0, 210.6)` | **WP 111** | `(-120.8, 207.2)` | 3.5 m | **1:1 Native Match** |
| **2nd Gate** | `Gate` | `(14.0, 425.1)` | **WP 33** | `(19.5, 414.6)` | 11.8 m | **1:1 Native Match** |
| **GymKhaana** | `Building.010` | `(-183.8, -130.4)` | **WP 274** | `(-180.1, -128.6)` | 4.1 m | **1:1 Native Match** |
| **Sigma Block** | `Building.009` | `(-71.8, -236.3)` | **WP 255** | `(-65.4, -238.2)` | 6.7 m | **1:1 Native Match** |
| **Academic Block 1** | `Building.007` | `(-97.1, -130.0)` | **WP 241** | `(-92.4, -117.2)` | 13.6 m | **1:1 Native Match** |
| **Swimming Pool** | `Building.008` | `(237.3, 184.5)` | **WP 192** | `(227.2, 177.9)` | 12.1 m | **1:1 Native Match** |
| **Volleyball Court** | `Building.018` | `(-92.1, 39.7)` | **WP 155** | `(-90.3, 39.4)` | 1.8 m | **1:1 Native Match** |

### Mathematical Conclusion:
1. **Scale**: Exactly 1:1 metric scale. No scaling transform required.
2. **Rotation**: $0^\circ$ yaw offset. The X and Z axes correspond identically to local campus coordinates.
3. **Elevation**: Elevation in `waypoints.json` is uniform $Y = 0.0$ (ground plane), whereas GLB meshes have slight topographic relief (Y: -49.7m to 41.2m). Waypoint pins and road lines are rendered at $Y = \text{ground} + 1.2\text{m}$ to float cleanly above road asphalt geometry without z-fighting.

## ⚡ Digital Twin Telemetry: Mahatma Gandhi Auditorium

The Digital Twin simulates venue telemetry for **Building024** (Mahatma Gandhi Auditorium, entrance waypoint 199):

* **Rated Capacity**: 2,400 seats *(configurable demo value)*.
* **Current Occupancy**: Dynamically updating simulated attendee count.
* **Utilization Percentage**: Real-time gauge calculation.
* **Configurable Alert Thresholds**:
  * **Low / Normal**: $< 50\%$ (Green) — Nominal traffic, unobstructed exits.
  * **Moderate**: $50\% - 80\%$ (Amber) — Steady flow, standard auditorium sessions.
  * **High**: $> 80\%$ (Orange) — Near capacity, auxiliary doors prepared.
  * **Overcapacity Alert**: $> 100\%$ (Red) — Warning triggered, ingress throttling suggested.
* **Simulation Modes**:
  * **Auto-Tick**: Automatic Poisson-like drift of attendee ingress/egress every 2.5 seconds.
  * **Manual Control**: Direct numeric input and slider override.
  * **Scenario Presets**: *Empty Venue (65)*, *Lecture Class (1,000)*, *Cultural Event (1,820)*, *Convocation Full House (2,250)*, and *Overcapacity Alert (2,550)*.

> [!WARNING]
> **Telemetry Disclaimer**: Occupancy figures, flow rates, and capacity thresholds are simulated demonstration values. Real-world VIT Chennai production deployments require live integration with campus IoT access control, turnstiles, or optical edge sensors.

## ☁️ AWS Cloud Architecture Migration Roadmap

To transition this local standalone prototype into a scalable cloud-native digital twin on AWS:

```
[ Edge Devices (Campus Turnstiles / Optical Sensors) ]
                          │
                   MQTT over mTLS
                          ▼
            [ AWS IoT Core Message Broker ]
                          │
                 IoT Rules Engine
                          ▼
             [ Amazon Kinesis Data Streams ]
                          │
                          ▼
                   [ AWS Lambda ] ─── SNS Alerts (High Occupancy)
                    │          │
         Hot Telemetry         Metadata & Venue Config
                    │          │
                    ▼          ▼
          [ Amazon Timestream ]  [ Amazon DynamoDB ]
                    │
                    ▼
          [ AWS IoT TwinMaker ] ◄── 3D Scene Graph Binding
                    │
                    ▼
      [ Amazon API Gateway (WebSocket API) ]
                    │
                    ▼
     [ Static Web Client (Amazon S3 + CloudFront CDN) ]
```

1. **Edge Ingestion (AWS IoT Core)**: Ingests real-time optical people-counters and turnstile check-ins over MQTT (`vitc/campus/building024/telemetry`) with X.509 device certificates.
2. **Stream Processing (Amazon Kinesis & Lambda)**: Low-latency buffering and serverless compute to sanitize ticks, compute rolling occupancy, and trigger Amazon SNS alerts when occupancy exceeds 80%.
3. **Hot & Cold Storage (Amazon Timestream & DynamoDB)**: Timestream stores sub-second time-series history for analytics; DynamoDB stores campus metadata and current state cache.
4. **Spatial Twin (AWS IoT TwinMaker)**: Connects 3D entities in `vit_map.glb` to live Timestream metrics with visual tag alarms.
5. **Global Delivery (Amazon S3 & CloudFront)**: Serves the WebGL application and 20MB GLB asset with edge caching, while an API Gateway WebSocket feeds telemetry to the browser.

## 🚀 Setup & How to Run

### Prerequisites
* **Node.js**: v18+ (tested on Node v24)
* **npm**: v9+ (tested on npm 11)

### Option 1: Development Server (Vite)
```bash
# 1. Install dependencies
npm install

# 2. Run local development server
npm run dev

# Open http://localhost:5173 in any modern browser
```

### Option 2: Production Build & Preview
```bash
# 1. Compile production bundle
npm run build

# 2. Preview production distribution
npm run preview

# Open http://localhost:4173
```

### Option 3: Python Fallback Static Server
```bash
# The compiled bundle in dist/ or public/ can be served by any HTTP server:
python -m http.server 8000 --directory dist

# Open http://localhost:8000
```
